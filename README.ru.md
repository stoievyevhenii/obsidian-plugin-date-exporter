# Daily Notes TXT Export

Плагин Obsidian для desktop и Android: выбирает ежедневные Markdown-заметки за произвольный период и сохраняет **один Markdown** в vault. Каждый файл выводится отдельным блоком: жирная дата `YYYY-MM-DD`, все properties в таблице из двух столбцов с жирными названиями, разделитель `=====` и строки заметки. Группировка по Company/Ship и автоматическая нумерация отключены. Исходники — TypeScript; `main.js` уже собран. Компиляция для установки не нужна.

## Установка вручную

1. Распакуйте **daily-notes-txt-export-1.1.2.zip**. Внутри находится папка `daily-notes-txt-export`.
2. Скопируйте эту папку в каталог плагинов вашего vault:

   ```text
   <vault>/.obsidian/plugins/daily-notes-txt-export/
     main.js
     manifest.json
     styles.css
     README.md
     LICENSE
     THIRD_PARTY_NOTICES.md
   ```

3. В Obsidian откройте **Настройки → Сторонние плагины / Community plugins**. При необходимости отключите ограниченный режим, затем перезапустите Obsidian и включите **Daily Notes TXT Export**.
4. Если в Obsidian изменена папка конфигурации, используйте её вместо `.obsidian`.

**На Android:** включите отображение скрытых файлов в файловом менеджере. Копировать нужно в папку именно того vault, который открыт на телефоне. Если файловый менеджер не даёт открыть расположение vault, установите на компьютере и синхронизируйте папку плагина либо используйте файловый менеджер с доступом к выбранному хранилищу. Проверьте отсутствие лишнего уровня `daily-notes-txt-export/daily-notes-txt-export/`. Полностью закройте и снова откройте приложение после копирования.

Минимальная версия Obsidian: **1.5.7**, `isDesktopOnly: false`. Компиляция дополнительно проверена с опубликованными типами API 1.5.7. Runtime использует Vault API и DOM/Web API; Node.js, Electron, абсолютные пути и сетевые запросы не используются. Библиотеки обработки Markdown включены в `main.js`.

**Обновление с 1.0.0:** отключите плагин, замените `main.js`, `manifest.json`, `styles.css` файлами из нового ZIP и включите его снова. Сохраните существующий `data.json`: настройки продолжат работать. Текущий формат Markdown: жирная дата `YYYY-MM-DD`, таблица properties, `=====` и исходные строки. Поиск вложенных папок включён по умолчанию.

## Первый экспорт

1. **Настройки → Daily Notes TXT Export**: укажите папку ежедневных заметок, например `Daily Notes`. Пустая папка означает корень vault. Нажмите **Сохранить настройки**.
2. Откройте палитру команд и выберите **Daily Notes TXT Export: Экспорт заметок за период в MD**. Также доступна кнопка со значком экспорта; на мобильном она находится в меню действий Obsidian.
3. Выберите даты. При открытии с **1 по 7 число** подставляются первая и последняя даты **предыдущего месяца**; с **8 числа** — **текущего месяца**. Используется местная дата устройства на момент открытия окна. Например, 7 ноября: 1–31 октября; 8 ноября: 1–30 ноября. Диапазон можно изменить вручную, обе границы включаются. Системное поле даты может показывать дату в локальном формате; внутри используются строгие даты `YYYY-MM-DD`.
4. При необходимости раскройте **Папки, формат имени и задачи**. Эти изменения применятся только к текущему экспорту.
5. Нажмите **Сформировать отчёт**. Откроется текстовый предпросмотр, и Markdown автоматически сохранится в vault. Дождитесь строки **Сохранено: …**. При ошибке записи доступны текст и **Повторить сохранение**.

По умолчанию результат:

```text
Reports/Daily-report_2026-10-01_2026-10-31.md
```

Следующий экспорт создаёт `Daily-report_2026-10-01_2026-10-31 (2).md`. Каждый запуск создаёт один новый Markdown; существующие файлы не перезаписываются. Папка отчётов создаётся автоматически. Текст — Unicode UTF-8 без BOM, переводы строк LF, одна пустая строка между блоками файлов.

## Настройки

| Настройка | По умолчанию | Значение |
| --- | --- | --- |
| Папка Daily Notes | пусто | Относительный путь; пусто = корень vault |
| Формат имени | `YYYY-MM-DD` | Расширение `.md` можно указать или опустить |
| Включать вложенные папки | Да | Находит одноимённые даты в папках разных судов |
| Папка отчётов | `Reports` | Относительный путь; пусто = корень vault |
| Какие пункты включать | Текст, списки и чекбоксы | Или только чекбоксы |
| Включать выполненные | Да | При отключении исключаются `[x]` / `[X]` |

Папка и формат задаются **в настройках этого плагина**. Они не импортируются автоматически из встроенного Daily Notes или Periodic Notes. Встроенный Daily Notes для экспорта не обязателен.

Формат имени поддерживает точные числовые токены **`YYYY`, `MM`, `DD`**, каждый должен присутствовать. Примеры:

| Формат | Файл относительно папки Daily Notes |
| --- | --- |
| `YYYY-MM-DD` | `2026-10-23.md` |
| `DD.MM.YYYY.md` | `23.10.2026.md` |
| `YYYY/MM/YYYY-MM-DD` | `2026/10/2026-10-23.md` |
| `[Дневник-]DD-MM-YYYY` | `Дневник-23-10-2026.md` |

Это явно ограниченный, независимый от языка набор токенов: `MMM`, `M`, `D`, `ddd`, `yyyy` не поддерживаются. Буквальный текст заключайте в `[скобки]`. При повторении токенов в подпапке и имени значения должны совпадать. При включённом поиске вложенных папок формат сопоставляется с концом пути относительно выбранной папки: для `YYYY-MM-DD` подходят и `Daily/Ship 1/2026-10-24.md`, и `Daily/Ship 2/2026-10-24.md`. Формат `YYYY/MM/YYYY-MM-DD` также работает внутри папок судов. Если отключить вложенные папки, нужен полный путь относительно папки Daily Notes, как в версии 1.0.0. Файлы за пределами выбранной папки не читаются.

Отсутствующие и пустые дни пропускаются. Проверяются реальные даты, включая високосные годы и порядок границ. Количество дней не ограничено: просматриваются существующие Markdown-файлы, а не все календарные дни периода. Абсолютные пути, скрытые папки, `..` и недопустимые для desktop символы запрещены.

## Что извлекается

- Обычные строки текста без маркеров: каждая непустая строка основного текста становится отдельным пунктом.
- Маркированные `-`, `*`, `+` и нумерованные `1.` / `1)` списки.
- Открытые, завершённые и пользовательские чекбоксы: `[ ]`, `[x]`, `[X]`, `[/]`, `[!]` и другие одиночные статусы.
- Вложенные пункты — отдельные строки; текст дочерних пунктов не дублируется в родителе.
- Продолжения пунктов остаются на отдельных строках. Исходные маркеры, чекбоксы, номера и отступы сохраняются; новые номера не добавляются.
- Списки внутри цитат и callout-блоков также включаются.
- Заголовки, блоки кода и HTML-/Obsidian-комментарии исключаются. YAML frontmatter выводится отдельными properties над разделителем. Пустые пункты и пустые чекбоксы исключаются.
- Inline-разметка, ссылки и inline-код сохраняются как в исходной строке.
- Каждый файл выводится отдельно: жирная дата, таблица properties, `=====` и выбранные строки. Группировка и объединение по Company/Ship не выполняются.

Плагин экспортирует исходный Markdown. Динамический результат Dataview/Tasks-запросов, содержимое встроенных заметок и сторонних шаблонов не вычисляется. Пункты внутри таблиц не считаются Markdown-списками.

## Properties и формат отчёта

Экспортируются все поля YAML properties в начале файла, в порядке чтения. Таблица содержит два столбца — «Свойство» и «Значение»; названия свойств выделены жирным. Имена полей не ограничены Company/Ship. Спецсимволы экранируются, чтобы сохранить структуру таблицы и буквальный текст значений.

Исходная заметка `2026-10-24.md`:

```markdown
---
Company: ShipCompany
Ship: Ship 1
tags: [work, urgent]
---
- [x] Подготовить отчёт
- [ ] Созвониться с командой
```

Результат:

```markdown
**2026-10-24**

| Свойство | Значение |
| --- | --- |
| **Company** | ShipCompany |
| **Ship** | Ship 1 |
| **tags** | work, urgent |

=====

- [x] Подготовить отчёт
- [ ] Созвониться с командой
```

После жирной даты идёт таблица properties, затем ровно пять знаков равно и строки заметки. Разделы отделены пустыми строками для корректного отображения Markdown. Списки значений properties объединяются через запятую, числа и флаги выводятся текстом, null — пустым значением. Переносы в текстовом свойстве заменяются пробелами; вложенные объекты выводятся компактным JSON, ссылки сохраняются в исходном виде. Ошибочный YAML прерывает экспорт с указанием файла.

Даты сортируются по возрастанию. Несколько файлов с одинаковой датой выводятся отдельными блоками в порядке пути файла; их свойства и списки не объединяются. Между блоками — пустая строка. При отсутствии properties после даты сразу идёт `=====`. Файл без подходящих строк пропускается, даже если properties заполнены.

Примеры заметок и ожидаемые Markdown: `examples/expected.md` и `examples/grouped-expected.md`. Историческое имя второго примера сохранено; теперь он показывает отдельные блоки файлов одной даты.

## Копирование и отправка на Android

В окне результата есть **Копировать**, **Поделиться** и **Выделить всё**. Кнопки вызываются отдельным нажатием после подготовки отчёта, как требуется для системного обмена.

- **Копировать**: сначала Clipboard API, затем копирование выделенного текста. Если WebView запрещает оба способа, текст остаётся выделенным: удерживайте его и выберите **Копировать** в Android, затем вставьте в нужное приложение.
- **Поделиться**: Web Share API отправляет Markdown-файл, если WebView сообщает поддержку файлов; иначе отправляет текст. Если API отсутствует или запрещён, плагин показывает подсказку и выделяет текст. Отмена системного диалога не считается ошибкой.
- Если в меню выделения Android есть **Поделиться**, можно использовать его. Сохранённый Markdown также можно отправить через файловый менеджер из папки `Reports` вашего vault.

У Obsidian нет публичного универсального API исходящего системного обмена. Доступность нативного диалога зависит от Obsidian, Android WebView и устройства; он **не гарантируется на каждом Android**. Копирование с ручным резервным способом и сохранение в vault от него не зависят. Плагин не использует внутренние Capacitor-мосты Obsidian.

## Ошибки и сохранность данных

Отсутствующая Daily Notes-папка, неверный формат имени или обратный диапазон показывают понятную ошибку. Если файлы не соответствуют формату или все пункты исключены, показывается число найденных заметок и Markdown не создаётся. Ошибка чтения любой подходящей заметки прерывает подготовку целиком: неполный отчёт не записывается.

Закрытие окна выбора периода отменяет незавершённое чтение. Когда окно результата уже открыто и начата запись, она завершается даже после закрытия окна; сообщение покажет путь сохранённого Markdown. Исходные заметки не изменяются. Отчёты хранятся локально; их дальнейшая синхронизация определяется настройками вашего vault.

## Разработка и проверки

Нужны Node.js **22.22+ в ветке 22.x** и npm на компьютере для сборки; на Android они не нужны.

```sh
npm ci
npm test
npm run build
node scripts/check-bundle.mjs
```

Или `npm run verify` для всех проверок. `npm run dev` отслеживает изменения исходников. После сборки обновите `main.js` в установленной папке и перезагрузите плагин.

`npm run package -- --out ./release` сначала выполняет проверки и сборку, затем создаёт установочную папку, ZIP для установки и ZIP с исходниками. Состав исходников задан разрешённым списком. В исходный ZIP не включаются сгенерированный `main.js`, `node_modules`, `data.json`, `.env` и промежуточные файлы. Инструкция публикации: [PUBLICATION.md](PUBLICATION.md), английское описание: [README.md](README.md).

Тесты проверяют преобразование, даты, настройки, фильтрацию файлов по папке и периоду, отмену чтения, ошибки, конфликты имён, копирование/отправку и полный поток UI с имитацией Obsidian API. `check-bundle.mjs` проверяет итоговый CommonJS, отсутствие Node API и загрузку собранного плагина. Фактически выполненные проверки и ограничения записаны в `VALIDATION.md`.

Подтверждение на физическом Android и в установленном Obsidian выполняется пользователем: установить плагин, экспортировать `examples/Daily Notes`, сравнить результат с `examples/expected.md`, проверить копирование и системный обмен. Автоматические тесты с имитацией API не заменяют такой запуск.
